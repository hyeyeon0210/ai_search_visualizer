탐색 알고리즘 개념 정리

탭을 눌러 맹목적 탐색과 경험적 탐색, 그리고 그 안의 구체적인 알고리즘들을 순서대로 살펴보세요. 각 알고리즘의 의사코드는 시뮬레이터에서 실제로 실행되는 로직과 동일합니다.

맹목적 탐색 (Uninformed / Blind Search)

맹목적 탐색은 지금 살펴보는 상태가 목표에 얼마나 가까운지에 대한 어떤 힌트도 없이, 오직 "어떤 순서로 상태를 확장할 것인가"라는 규칙만으로 탐색하는 방법입니다. 문제에 대한 추가 지식(휴리스틱) 없이도 적용할 수 있다는 뜻에서 "정보 없는 탐색(uninformed search)"이라고도 부릅니다.

대표적으로 다음 두 가지가 있으며, 차이는 오직 프론티어(frontier, 아직 확장하지 않은 후보 상태들의 목록)를 어떤 자료구조로 관리하느냐입니다.

알고리즘프론티어확장 순서
너비 우선 탐색큐 (FIFO)먼저 발견한 상태부터
깊이 우선 탐색스택 (LIFO)가장 최근에 발견한 상태부터
같은 문제라도 프론티어 자료구조 하나만 바꾸면 완전히 다른 순서로 상태 공간을 탐색하게 됩니다 — 두 시뮬레이터에서 같은 문제를 BFS와 DFS로 각각 돌려보고 탐색 로그의 순서를 비교해보세요.

너비 우선 탐색 (Breadth-First Search, BFS)

시작 상태에서 가까운 상태부터 한 단계(층)씩 순서대로 탐색합니다. 마치 호수에 돌을 던졌을 때 물결이 동심원으로 퍼져나가는 모습과 같습니다. 프론티어를 큐(Queue, 선입선출)로 관리하기 때문에, 먼저 발견된 상태가 먼저 확장됩니다. 

BFS(시작상태):
    큐 ← [시작상태]
    방문집합 ← { }
    while 큐가 비어있지 않으면:
        node ← 큐.맨앞에서_꺼내기()
        if node가 목표상태이면:
            return 경로(node)
        방문집합에 node 추가
        for 이웃 in 후계함수(node):
            if 이웃이 방문집합에 없으면:
                큐.맨뒤에_넣기(이웃)
    return 실패
장점
  • 모든 이동 비용이 같다면(예: 8-퍼즐의 한 칸 이동) 항상 최단 경로를 찾음
  • 목표가 시작점에서 가까울 때 매우 효율적
단점
  • 같은 층의 상태를 모두 저장해야 해서 메모리 사용량이 큼
  • 목표가 깊은 곳에 있으면 매우 느려짐

깊이 우선 탐색 (Depth-First Search, DFS)

한 방향으로 갈 수 있는 만큼 끝까지 파고든 뒤, 더 갈 곳이 없으면 되돌아와 다른 방향을 시도합니다. 미로를 한쪽 벽에 손을 대고 끝까지 따라가 보는 방식과 비슷합니다. 프론티어를 스택(Stack, 후입선출)으로 관리하기 때문에, 가장 최근에 발견된 상태부터 먼저 확장됩니다. 

DFS(시작상태):
    스택 ← [시작상태]
    방문집합 ← { }
    while 스택이 비어있지 않으면:
        node ← 스택.맨위에서_꺼내기()
        if node가 목표상태이면:
            return 경로(node)
        방문집합에 node 추가
        for 이웃 in 후계함수(node):
            if 이웃이 방문집합에 없으면:
                스택.맨위에_넣기(이웃)
    return 실패
장점
  • 현재 탐색 경로만 기억하면 되어 메모리 사용량이 적음
  • 해가 깊은 곳에 있고 트리가 넓을 때 BFS보다 빨리 해를 찾을 수도 있음
단점
  • 최단 경로를 보장하지 않음 (엉뚱한 방향으로 깊이 들어갈 수 있음)
  • 순환/무한히 깊은 공간에서는 깊이 제한이 없으면 끝나지 않을 수 있음
깊이 제한 탐색 (Depth-Limited Search) — DFS가 엉뚱한 방향으로 한없이 깊게 파고드는 것을 막기 위해, 미리 정한 최대 깊이까지만 탐색하도록 제한하는 방법입니다. 8-퍼즐 시뮬레이터의 DFS는 이 기법을 적용해, 정답이 존재함이 보장되는 깊이까지만 탐색합니다.

경험적 탐색 (Informed / Heuristic Search)

경험적 탐색은 휴리스틱 함수 h(n) — "상태 n이 목표로부터 얼마나 떨어져 있을 것 같은가"를 추정하는 함수 — 을 활용해, 유망해 보이는 상태부터 먼저 탐색하는 방법입니다. 사람이 경험/직관을 바탕으로 "이쪽이 더 가까운 것 같다"고 판단하는 과정을 흉내 낸다는 뜻에서 "발견적 탐색"이라고도 부릅니다. 문제에 대한 추가 지식을 활용하므로 "정보 기반 탐색(informed search)"이라고도 합니다.

알고리즘정렬 기준의미
최상 우선 탐색h(n)목표까지 남은 거리 추정치만 사용
A* 탐색f(n) = g(n) + h(n)지금까지 온 비용 + 남은 거리 추정치
8-퍼즐에서는 보통 맨해튼 거리(각 타일이 목표 위치까지 가로+세로로 몇 칸 떨어져 있는지의 합)를 h(n)으로 사용합니다. 휴리스틱이 실제 남은 비용보다 항상 작거나 같으면(=과대평가하지 않으면) "admissible(허용 가능)"하다고 하며, 이 조건을 만족하는 h(n)을 사용하는 A*는 최적 경로를 보장합니다.

최상 우선 탐색 (Best-First Search / Greedy)

프론티어에 있는 상태들 중 휴리스틱 값 h(n)이 가장 작은(=목표에 가장 가까워 보이는) 상태를 항상 먼저 확장합니다. 지금까지 온 거리(비용)는 전혀 고려하지 않고 오직 "남은 거리 추정치"만 보기 때문에 탐욕적 (greedy) 알고리즘이라고도 부릅니다. 

최상우선탐색(시작상태):
    우선순위큐 ← [시작상태]   # h(n) 오름차순 정렬
    방문집합 ← { }
    while 우선순위큐가 비어있지 않으면:
        node ← 우선순위큐에서_h가_가장_작은_것_꺼내기()
        if node가 목표상태이면:
            return 경로(node)
        방문집합에 node 추가
        for 이웃 in 후계함수(node):
            if 이웃이 방문집합에 없으면:
                우선순위큐.삽입(이웃, 기준값 = h(이웃))
    return 실패
장점
  • 휴리스틱이 좋다면 매우 빠르게 해를 찾음
  • 구현이 간단함
단점
  • 지금까지 든 비용을 무시하므로 최적 경로를 보장하지 않음
  • 휴리스틱이 나쁘면 엉뚱한 방향으로 계속 탐색할 수 있음

A* 탐색 (A-Star Search)

최상 우선 탐색의 "목표까지 남은 거리(h)만 보는" 단점을 보완하기 위해, 지금까지 실제로 이동한 비용 g(n)과 남은 거리 추정치 h(n)을 더한 f(n) = g(n) + h(n)이 가장 작은 상태를 먼저 확장합니다. 경험적 탐색을 대표하는 알고리즘으로, 게임의 길찾기(NPC 이동 경로 계산)나 내비게이션 경로 탐색 등 실제로 널리 쓰입니다. 

A*(시작상태):
    우선순위큐 ← [시작상태]   # f(n)=g(n)+h(n) 오름차순 정렬
    방문집합 ← { }
    while 우선순위큐가 비어있지 않으면:
        node ← 우선순위큐에서_f가_가장_작은_것_꺼내기()
        if node가 목표상태이면:
            return 경로(node)
        방문집합에 node 추가
        for 이웃 in 후계함수(node):
            g(이웃) ← g(node) + 이동비용(node, 이웃)
            if 이웃이 더_좋은_경로로_방문된_적_없으면:
                f(이웃) ← g(이웃) + h(이웃)
                우선순위큐.삽입(이웃, 기준값 = f(이웃))
    return 실패
장점
  • h(n)이 admissible(과대평가하지 않음)하면 항상 최적 경로를 찾음
  • 맹목적 탐색보다 훨씬 적은 노드만 확장하는 경우가 많음
단점
  • 좋은 휴리스틱을 설계하기 어려운 문제도 있음
  • 상태 공간이 매우 크면 우선순위 큐 관리 비용이 커질 수 있음
직접 확인해보고 싶다면 8-퍼즐 시뮬레이터 또는 틱택토 시뮬레이터에서 같은 문제를 네 가지 알고리즘으로 각각 실행해보고, 확장한 노드 수와 찾은 경로의 길이를 비교해보세요.
